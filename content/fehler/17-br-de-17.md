h1: BR-DE-17 (Warnung): Rechnungsart (BT-3) nicht vorgesehen
meldung: [BR-DE-17] Mit dem Element "Invoice type code" (BT-3) sollen ausschließlich folgende Codes aus der Codeliste UNTDID 1001 übermittelt werden: 326 (Partial invoice), 380 (Commercial invoice), 384 (Corrected invoice), 389 (Self-billed invoice) und 381 (Credit note),875 (Partial construction invoice), 876 (Partial final construction invoice), 877 (Final construction invoice).
detects: yes

**Kurz erklärt.** Diese Meldung ist eine **Warnung**, kein Fehler. Sie besagt: Die Rechnungsart in Ihrer Datei gehört nicht zu den Codes, die XRechnung vorsieht. Ob Ihr Empfänger die Rechnung trotzdem verarbeitet, hängt von seinem Programm ab. Sicherer ist ein Code aus der Liste.

**Was die Regel genau prüft.** Im UBL-Format muss `cbc:InvoiceTypeCode` (bei Gutschriften `cbc:CreditNoteTypeCode`) einer dieser acht Werte sein: 326, 380, 381, 384, 389, 875, 876, 877. Im XRechnung-Regelwerk ist die Regel ausdrücklich als Warnung eingestuft („sollen“, nicht „müssen“).

## Erlaubte Codes

| Code | Bedeutung |
|---|---|
| `380` | Rechnung |
| `326` | Teilrechnung |
| `384` | Korrigierte Rechnung |
| `389` | Gutschrift im Gutschriftverfahren (Selbstfakturierung) |
| `381` | Gutschrift (Credit note) |
| `875` | Abschlagsrechnung (Bauleistung) |
| `876` | Teilschlussrechnung (Bauleistung) |
| `877` | Schlussrechnung (Bauleistung) |

## Typische Ursachen

- Anzahlungs- oder Vorauszahlungsrechnungen werden mit einem eigenen Code (zum Beispiel `386`) ausgegeben, den XRechnung nicht vorsieht.
- Das Programm übernimmt eine interne Belegart als Code.
- Eine Vorlage aus einem anderen Land oder einem anderen Format wurde ohne Anpassung übernommen.

## So beheben Sie es

1. Prüfen Sie, welche Rechnungsart Ihre Datei angibt.
2. Wählen Sie den passenden Code aus der Tabelle. Für eine normale Rechnung ist das `380`, für eine Teil- oder Anzahlungsrechnung meist `326`.
3. Klären Sie bei Bau-Abschlagsrechnungen mit Ihrem Empfänger, ob er `875` bis `877` verarbeitet.
4. Erzeugen Sie die Rechnung neu.

**Vorher (Warnung)**

```xml
<cbc:InvoiceTypeCode>386</cbc:InvoiceTypeCode>
```

**Nachher**

```xml
<cbc:InvoiceTypeCode>326</cbc:InvoiceTypeCode>
```

**Häufig zusammen mit:** BR-CL-01 (Code nicht in der Codeliste UNTDID 1001), wenn der Code gar nicht existiert.

## Häufige Fragen

- *Muss ich die Warnung beheben?* Die Rechnung scheitert an dieser Regel nicht. Der Empfänger sieht die Warnung aber im Prüfbericht und kann nachfragen oder ablehnen.
- *Welcher Code für eine Anzahlungsrechnung?* XRechnung sieht keinen eigenen Code dafür vor. Üblich ist `326` (Teilrechnung). Stimmen Sie das mit Ihrem Empfänger ab.

h1: BR-CL-23: Ungültige Mengeneinheit („Std“, „Stk“)
meldung: [BR-CL-23] Unit code MUST be coded according to the UN/ECE Recommendation 20 with Rec 21 extension
detects: yes

**Kurz erklärt.** Mengeneinheiten müssen als genormter Code angegeben werden, nicht als Abkürzung. „Std“, „Stk“ oder „Pauschal“ sind keine gültigen Codes. In unserem Test hat der offizielle KoSIT-Validator (1.6.3, XRechnung 3.0.2) eine solche Rechnung angenommen, den Fehler aber gemeldet. Das Programm Ihres Empfängers kann strenger sein.

**Was die Regel genau prüft.** Das Attribut `unitCode` an `cbc:InvoicedQuantity`, `cbc:CreditedQuantity` und `cbc:BaseQuantity` muss in der Codeliste UN/ECE Recommendation 20 (mit Rec 21) stehen. Groß- und Kleinschreibung zählt, Leerzeichen sind nicht erlaubt.

## Häufige Codes

| Einheit | Code |
|---|---|
| Stunde | `HUR` |
| Stück | `H87` oder `C62` |
| Tag | `DAY` |
| Monat | `MON` |
| Kilogramm | `KGM` |
| Meter | `MTR` |
| Pauschale | `LS` |

## Typische Ursachen

- Das Programm übernimmt die Einheit aus dem Artikelstamm als Freitext.
- Eigene Einheiten („Lizenz“, „Paket“) wurden nie einem Code zugeordnet.
- Shop-Plugins setzen für alle Positionen „Stk“.

## So beheben Sie es

1. Ordnen Sie jeder Einheit den passenden Code zu (siehe Tabelle).
2. Hinterlegen Sie die Zuordnung im Artikel- oder Einheitenstamm.
3. Erzeugen Sie die Rechnung neu.

**Vorher (Fehler gemeldet)**

```xml
<cbc:InvoicedQuantity unitCode="Std">8</cbc:InvoicedQuantity>
```

**Nachher**

```xml
<cbc:InvoicedQuantity unitCode="HUR">8</cbc:InvoicedQuantity>
```

## Häufige Fragen

- *Der Validator hat die Rechnung angenommen. Muss ich das trotzdem ändern?* Ja. Der Fehler steht im Bericht, und der Empfänger kann die Rechnung deswegen zurückweisen.
- *Welcher Code für Lizenzen oder Pakete?* Meist `C62` (Einheit) oder `LS` (Pauschale).

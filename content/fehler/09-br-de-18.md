detects: no

*Vollständiger Originaltext (XRechnung-Schematron, am Anfang gekürzt):* „Die Informationen zur Gewährung von Skonto müssen wie folgt im Element "Payment terms" (BT-20) übermittelt werden: Anzugeben ist im ersten Segment "SKONTO", im zweiten "TAGE=n", im dritten "PROZENT=n". …“

**Kurz erklärt.** Wenn Sie Skonto gewähren, muss die Angabe in den Zahlungsbedingungen (BT-20) einem festen Muster folgen, damit der Empfänger sie automatisch verarbeiten kann. Ein freier Satz wie „2 % Skonto bei Zahlung in 14 Tagen“ genügt nicht, sobald eine Zeile mit `#` beginnt.

**Was die Regel genau prüft.** Jede Zeile in BT-20, die mit `#` beginnt, muss so aussehen: `#SKONTO#TAGE=14#PROZENT=2.00#`, optional mit `#BASISBETRAG=1000.00#`. Prozent mit Punkt und genau zwei Nachkommastellen, alles in Großbuchstaben, keine Leerzeichen. Nach der letzten Skontozeile muss ein Zeilenumbruch folgen. Freier Text ohne `#` am Zeilenanfang wird nicht geprüft.

## Typische Ursachen

- Prozentsatz mit Komma (`2,00`) oder ohne zwei Nachkommastellen (`2`).
- Leerzeichen oder Kleinbuchstaben (`#Skonto#`).
- Der abschließende Zeilenumbruch fehlt, oft weil das Programm Leerzeichen am Ende abschneidet.
- Zwei Skontostufen in einer Zeile.

## So beheben Sie es

1. Schreiben Sie jede Skontostufe in eine eigene Zeile.
2. Prozent immer mit Punkt und zwei Stellen: `PROZENT=2.00`.
3. Beenden Sie die Angabe mit einem Zeilenumbruch.

**Vorher (abgelehnt)**

```xml
<cac:PaymentTerms>
  <cbc:Note>#SKONTO#TAGE=14#PROZENT=2#</cbc:Note>
</cac:PaymentTerms>
```

**Nachher**

```xml
<cac:PaymentTerms>
  <cbc:Note>Zahlbar innerhalb von 30 Tagen.
#SKONTO#TAGE=14#PROZENT=2.00#
#SKONTO#TAGE=7#PROZENT=3.00#
</cbc:Note>
</cac:PaymentTerms>
```

## Häufige Fragen

- *Kann ich Skonto auch nur als Text schreiben?* Ja, wenn keine Zeile mit `#` beginnt. Dann kann der Empfänger das Skonto aber nicht automatisch berechnen.
- *Wofür ist BASISBETRAG?* Nur wenn Skonto nicht auf den ganzen Zahlbetrag gilt.

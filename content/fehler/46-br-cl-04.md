h1: BR-CL-04: Der Währungscode der Rechnung ist ungültig
meldung: [BR-CL-04]-Invoice currency code MUST be coded using ISO code list 4217 alpha-3
detects: yes

**Kurz erklärt.** Die Währung der Rechnung steht als dreistelliger Code in der Datei, zum Beispiel `EUR` für Euro oder `CHF` für Schweizer Franken. Steht dort ein Name wie „Euro“ oder ein Zeichen wie „€“, lehnt der Validator die Rechnung ab.

**Was die Regel genau prüft.** Im UBL-Format prüft die Regel das Element `cbc:DocumentCurrencyCode` (BT-5). Der Wert muss genau einer der Codes der Liste ISO 4217 sein, in Großbuchstaben. Leerzeichen am Anfang oder Ende spielen keine Rolle. Die Währung in den Betragsfeldern (`currencyID`) prüft eine eigene Regel, BR-CL-03.

## Typische Ursachen

- Im Programm ist die Währung als Text hinterlegt („Euro“, „EURO“) und wird so in die Datei übernommen.
- Das Währungszeichen `€` wird statt des Codes geschrieben.
- Der Code steht in Kleinbuchstaben (`eur`); die offizielle Liste enthält nur Großbuchstaben.

## So beheben Sie es

1. Prüfen Sie in den Einstellungen Ihres Programms das Feld für die Währung.
2. Tragen Sie den dreistelligen Code in Großbuchstaben ein: `EUR`, `CHF`, `USD`, `GBP`.
3. Verwenden Sie denselben Code auch in den Betragsfeldern (`currencyID`).
4. Erzeugen Sie die Rechnung neu.

**Vorher (abgelehnt)**

```xml
<cbc:DocumentCurrencyCode>Euro</cbc:DocumentCurrencyCode>
```

**Nachher**

```xml
<cbc:DocumentCurrencyCode>EUR</cbc:DocumentCurrencyCode>
```

**Häufig zusammen mit:** BR-05 (Währungscode fehlt ganz) und BR-CL-14 (Ländercode ungültig).

## Häufige Fragen

- *Darf die Rechnung in einer anderen Währung als Euro sein?* Ja, wenn der Code in der Liste ISO 4217 steht, zum Beispiel `CHF`. Für die Umsatzsteuer in Euro gibt es dann ein eigenes Feld, den Steuerwährungscode (BT-6).
- *Unser Programm schreibt `eur`. Reicht das?* Nein. Die Regel verlangt Großbuchstaben: `EUR`.
